# Лаба 1. Сортировки: музыкальный стриминг

Заготовка для первой лабораторной по алгоритмам и структурам данных: девять задач на сортировки, от вставок до поразрядной. Внутри заготовки решений, тесты из примеров и `make`-команды, чтобы собирать и проверять решения одной строкой.

Решений здесь нет. Их пишешь ты.

- Условия задач и дедлайн: [m3105.ru](https://m3105.ru/labs/algoritmy-i-struktury-dannyh/sortirovki-muzykalnyy-striming)
- Сдача: [контест на sort-me.org](https://sort-me.org/contest/674)

## Что нужно установить

- компилятор C++ с поддержкой C++20 (`g++` или `clang++`);
- `make`;
- `python3` для проверки тестов, без сторонних пакетов.

| Система | Команда |
| --- | --- |
| macOS | `xcode-select --install` |
| Ubuntu / Debian / WSL | `sudo apt install build-essential python3` |
| Arch | `sudo pacman -S base-devel python` |

На Windows проще всего работать через [WSL](https://learn.microsoft.com/ru-ru/windows/wsl/install).

## Как делать лабу

1. **Создай свой репозиторий.** Нажми **Use this template → Create a new repository** вверху страницы. Сделай репозиторий приватным, чтобы решения не утекли однокурсникам.

2. **Склонируй его** и зайди в папку:

   ```bash
   git clone https://github.com/<твой-ник>/<имя-репозитория>.git
   cd <имя-репозитория>
   ```

3. **Проверь, что всё собирается:**

   ```bash
   make test
   ```

   Все задачи будут с вердиктом `WA`: функции пока возвращают заглушки. Это нормально.

4. **Выбери задачу и прочитай условие** [на сайте](https://m3105.ru/labs/algoritmy-i-struktury-dannyh/sortirovki-muzykalnyy-striming).

5. **Напиши решение** в `tasks/<буква>.cpp`. Ввод и вывод уже написаны, менять нужно только тело функции с `// TODO`. Вспомогательные функции добавляй рядом.

6. **Проверь на тестах:**

   ```bash
   make a
   ```

   Пока есть `WA`, `RE` или `TL`, возвращайся к шагу 5. Если упало с `RE` и непонятно где, запусти с санитайзерами: `make a SAN=1` покажет строку, на которой программа вышла за границы массива.

7. **Добавь свои тесты.** Примеров из условия мало, и на sort-me тесты гораздо злее: большие `n`, одинаковые элементы, уже отсортированные массивы. Подробнее в разделе [Свои тесты](#свои-тесты).

8. **Отправь `tasks/<буква>.cpp` на [sort-me.org](https://sort-me.org/contest/674)**, компилятор GNU C++20. Файл самодостаточный, его можно прикреплять как есть.

9. **Закоммить решение:**

   ```bash
   git add tasks/a.cpp tests/a
   git commit -m "A: сортировка вставками"
   git push
   ```

Дальше то же самое для остальных задач. В конце `make test` должен показать `Проходят все тесты: 9 из 9`.

## Команды

| Команда | Что делает |
| --- | --- |
| `make` | показывает список команд |
| `make a` … `make i` | собирает задачу и прогоняет её тесты |
| `make test` | прогоняет тесты всех задач и печатает сводку |
| `make run-a` | собирает задачу и запускает её, ввод с клавиатуры (конец ввода: `Ctrl+D`) |
| `make a SAN=1` | собирает с AddressSanitizer и UBSan: ловит выход за границы массива и неопределённое поведение |
| `make format` | форматирует решения по Google C++ Style Guide (нужен `clang-format`) |
| `make clean` | удаляет папку `build` |

Компилятор и флаги можно переопределить: `make a CXX=g++-14`.

## Работа в CLion, VS Code и Visual Studio

Для IDE в репозитории есть `CMakeLists.txt`: каждая задача — отдельная цель `a` … `i`, её можно запускать и отлаживать прямо из редактора.

- **CLion:** `File → Open` и выбрать папку репозитория. Цели появятся в списке конфигураций запуска.
- **VS Code:** поставить расширения C/C++ и CMake Tools, открыть папку и выбрать цель в нижней панели.
- **Visual Studio:** `File → Open → Folder`.

Тесты из IDE запускаются через CTest, проверка та же, что у `make`. Перед `ctest` задачу нужно собрать:

```bash
cmake -B cmake-build -DCMAKE_BUILD_TYPE=Release
cmake --build cmake-build --target a
ctest --test-dir cmake-build -R a --output-on-failure
```

В Debug-сборке лимиты времени и памяти не проверяются: без оптимизаций код работает в несколько раз медленнее.

## Как читать результат

```
A. Первые треки
  1      OK   0.003 с     1.6 МБ
  2      OK   0.002 с     1.6 МБ
  3      WA   0.002 с     1.6 МБ
         ожидалось: 20
         получено:  19
```

| Вердикт | Значение |
| --- | --- |
| `OK` | ответ верный, время и память в пределах лимита |
| `WA` | неверный ответ |
| `RE` | программа упала или вернула ненулевой код |
| `TL` | процессорное время больше 1 секунды |
| `ML` | пиковая память больше лимита задачи |
| `CE` | ошибка компиляции |

Если хотя бы один тест не прошёл, `make` завершается с ошибкой `Error 1`: так и задумано.

Время замеряется на твоём компьютере, а не на сервере sort-me. Если локально решение работает 0.9 с, на сервере оно легко может не уложиться. Ответы сравниваются по словам: лишние пробелы и переводы строк не важны.

В задаче H правильных ответов несколько, поэтому вместо сравнения с файлом проверяется сам набор хедлайнеров.

## Свои тесты

Тест — это пара файлов в папке `tests/<буква>/`: `<имя>.in` с входными данными и `<имя>.out` с правильным ответом. Имя любое, `make` подхватит новые файлы сам.

```
tests/b/
├── 1.in          пример из условия
├── 1.out
├── sorted.in     свой тест: уже отсортированный массив
└── sorted.out
```

Идеи, что проверить:

- `n = 1` и другие минимальные значения;
- все элементы одинаковые;
- массив уже отсортирован или отсортирован в обратном порядке;
- максимальный `n` из условия, чтобы проверить время и память;
- в задачах с генератором меняются только параметры в двух строках, поэтому большой тест занимает пару байт.

Правильный ответ для большого теста можно получить медленным, но очевидно верным решением.

## Требования к решениям

- Язык: GNU C++20.
- Стиль заготовок: Google C++ Style Guide. Только массивы и функции, без контейнеров и классов. Память выделяется через `new[]` и освобождается через `delete[]`.
- В задаче B нельзя пользоваться готовыми функциями сортировки.

## Частые проблемы

**`bits/stdc++.h` file not found.** Этого заголовка нет в clang на macOS. Подключай нужные заголовки явно: `<iostream>`, `<cstdint>` и так далее.

**`make: python3: No such file or directory`.** Установи Python 3 или укажи путь к нему: `make a PYTHON=python`.

**Локально `OK`, на sort-me `WA`.** Значит, примеров из условия не хватило. Подумай о крайних случаях из раздела [Свои тесты](#свои-тесты) и проверь переполнение: в D, F и I ответ не помещается в `int`.

**Локально `OK`, на sort-me `TL`.** Проверь, что сложность совпадает с ожидаемой в условии. Для B важно, что будет на отсортированном массиве и на массиве из одинаковых чисел.
